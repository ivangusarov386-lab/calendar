# Сайт-календарь на Google Таблице

Статический сайт (HTML/CSS/JS, без сборщиков). Данные читаются при каждой
загрузке страницы и смене месяца из Google Таблицы — без собственного
кэша на сайте, всегда «как есть» в моменте.

Источник данных — не Google Cloud Console и API-ключ, а **Apps Script Web
App**: маленькая программа, которая живёт прямо внутри самой таблицы
(Расширения → Apps Script) и отдаёт сайту JSON по запросу. Так проще для
настройки — не нужен отдельный проект в Google Cloud, ключи, домены; и
безопаснее — таблицу не обязательно открывать «по ссылке», Web App
работает от имени владельца независимо от того, кто зашёл на сайт.

## Структура

- `index.html` — разметка страницы
- `css/style.css` — стили (тёмная хром-тема, адаптивная сетка)
- `js/config.js` — **webAppUrl**, ссылка на развёрнутый Apps Script (см. ниже)
- `js/app.js` — вся логика: загрузка данных, рендер сетки, модалка мероприятия
- `apps-script/Code.gs` — код **для самой Google Таблицы** (не для сайта):
  отдаёт данные сайту (`doGet`) и добавляет в таблицу меню «Календарь» с
  двумя помощниками (см. ниже)
- `manifest.json`, `sw.js`, `icons/` — PWA: позволяют добавить сайт на
  экран телефона как отдельное приложение (см. раздел «PWA» ниже)

## PWA — установка на экран телефона

Сайт настроен как Progressive Web App: его можно «установить» на телефон
без App Store/Google Play — иконка на рабочем столе, открывается в своём
окне без адресной строки браузера.

**Как установить:**
- **Android (Chrome):** открыть сайт → меню (⋮) → «Добавить на главный
  экран» / «Установить приложение».
- **iPhone (только Safari, в Chrome на iOS не работает):** открыть сайт →
  кнопка «Поделиться» (квадрат со стрелкой) → «На экран «Домой»».

**Как это устроено:**
- `manifest.json` — имя, цвета, иконки приложения.
- `icons/` — иконки (сгенерированы в стиле сайта: тёмно-синий фон +
  «9ц»), нескольких размеров под разные системы.
- `sw.js` — service worker, обязательное техническое требование браузеров
  для установки PWA. **Важно:** он кэширует только статику сайта (HTML,
  CSS, JS, иконки) для офлайн-открытия — данные календаря из Google
  Таблицы через него **никогда** не кэшируются и не проходят, чтобы не
  сломать требование «всегда свежие данные» из ТЗ. Если меняете `sw.js`,
  версия кэша (`CACHE_NAME`) внутри файла — увеличьте её, чтобы у
  пользователей, уже установивших приложение, подтянулась новая версия.

**Push-уведомления** (например, «добавлено новое мероприятие») в это не
входят — это отдельная, более сложная задача (нужен сервер рассылки и
подписки пользователей), можно сделать отдельным шагом.

## Настройка (всё через саму таблицу, без Google Cloud Console)

### 1. Вставить скрипт в таблицу

1. Откройте вашу Google Таблицу с календарём.
2. Меню **Расширения → Apps Script**.
3. Откроется редактор кода с файлом `Code.gs` — выделите всё (Ctrl+A) и удалите.
4. Скопируйте содержимое файла [`apps-script/Code.gs`](apps-script/Code.gs)
   из этого репозитория и вставьте вместо удалённого.
5. Сохраните (значок дискеты или Ctrl+S).

### 2. Опубликовать Web App

1. В редакторе Apps Script нажмите синюю кнопку **«Развернуть»**
   («Deploy») в правом верхнем углу → **«Новое развёртывание»**.
2. Рядом с «Тип развёртывания» нажмите на шестерёнку ⚙ и выберите
   **«Веб-приложение»** («Web app»).
3. В настройках:
   - **Execute as / Выполнять как:** «Я» (ваш аккаунт).
   - **Who has access / У кого есть доступ:** «Все» («Anyone»).
     (Это не открывает саму таблицу — только позволяет сайту вызывать эту
     функцию; какие данные отдавать, решает код в `doGet`.)
4. Нажмите **«Развернуть»**.
5. Google попросит авторизовать доступ — это ожидаемо (скрипт обращается
   к вашей же таблице): выберите аккаунт → если увидите предупреждение
   «Google не проверил это приложение» → **«Дополнительные настройки»**
   («Advanced») → **«Перейти на страницу … (небезопасно)»** → «Разрешить».
6. После этого появится **URL веб-приложения** — ссылка вида
   `https://script.google.com/macros/s/AKfycb.../exec`. Скопируйте её.

### 3. Вставить ссылку на сайт

Откройте `js/config.js` в репозитории и вставьте скопированную ссылку в поле
`webAppUrl`.

### Если позже меняете код в `Code.gs`

Просто сохранить файл — недостаточно, изменения не попадут на уже
опубликованный `/exec`-адрес, пока вы не создадите новую версию
развёртывания: **Развернуть → Управление развёртываниями** → у
существующего развёртывания нажать карандаш (редактировать) → в поле
«Версия» выбрать **«Новая версия»** → **«Развернуть»**. Ссылка остаётся той
же, обновлять её в `config.js` не нужно.

## Меню «Календарь» в самой таблице

После вставки скрипта (шаг 1 выше) и обновления страницы таблицы в меню
появится пункт **«Календарь»** с командами:

- **«Добавить лист на месяц…»** — спрашивает номер месяца и год, создаёт
  лист с нужным названием (`сентябрь`, `октябрь`, …), шапкой колонок и
  готовой строкой на каждый день месяца — вручную проставлять даты не нужно.
- **«Настроить проверку данных на текущем листе»** — то же самое для уже
  существующего листа: добавляет выпадающие списки в столбцы «Вид
  мероприятия» (список категорий) и «Участие» (`Да`/`Нет`). Опечатка в
  «Участие» (например, `да ` с пробелом) тихо ломает подсветку и цвет ячейки
  на сайте — валидация в таблице этого не допустит.
- **«Создать лист расписания…»** — спрашивает число уроков в день (это
  только стартовый шаблон, не ограничение) и создаёт лист `расписание`
  (Пн–Пт × N уроков, столбцы «День недели / № урока / Время / Предмет /
  Кабинет / Учитель»). Заполняете только реальные уроки — строки с пустым
  «Предмет» сайт просто не показывает, лишние можно не трогать.
- **«Добавить уроки к расписанию…»** — если уроков в какой-то день больше,
  чем заложено в шаблоне: спрашивает, сколько ещё уроков добавить, и
  дописывает их в конец каждого дня, продолжая нумерацию. Можно вызывать
  сколько угодно раз.

Список категорий (`EVENT_KINDS` в начале `Code.gs`) — пример
(`Собрание`, `Экскурсия`, `Праздник`, `Кружок`, `Другое`), отредактируйте под
реальные категории класса. Этот же список (с теми же цветами) зашит в сайте
как `CATEGORY_COLOR_MAP` в `js/app.js` — если меняете категории в скрипте,
обновите и цвета там же, чтобы легенда на сайте оставалась точной.

## Расписание уроков

Живёт на отдельном листе `расписание` **в той же таблице** — не в отдельном
документе: расписание проще для настройки (тот же Web App, то же меню в
таблице, никаких вторых ссылок/прав) и не имеет отношения к «Мероприятиям»
концептуально — строка там не про дату, а про день недели + номер урока,
одно и то же расписание повторяется каждую неделю (без чередования
чётная/нечётная).

На сайте вверху появился переключатель **«Мероприятия / Расписание»** —
показывает либо обычный календарь (с его собственным переключателем
Сетка/Список), либо расписание в виде карточек по дням недели со строками
уроков (время, кабинет, учитель). Расписание грузится один раз за сеанс
при первом открытии вкладки и дальше берётся из кэша в памяти, как и
мероприятия по месяцам.

## Хостинг

Обычный статический сайт — выложить рядом с остальными проектами на VPS
(достаточно раздать `index.html`, `css/`, `js/` через любой веб-сервер:
nginx, Apache и т.п.). Сборка не требуется.

## Решения по открытым вопросам ТЗ (раздел 7)

Часть пунктов требовала доступа к Google-аккаунту пользователя или данным,
которых ещё нет в таблице — по ним приняты решения по умолчанию, их при
необходимости легко поменять в `js/app.js`:

1. **Подключение к таблице** — исходно в ТЗ предполагался API-ключ через
   Google Cloud Console; вместо этого сайт читает данные через Apps Script
   Web App (см. «Настройка» выше) — то же самое требование («без задержки
   кэша») выполняется проще, без Cloud Console. Развернуть Web App и
   вписать ссылку в `js/config.js` можете только вы, это единственный шаг,
   который остаётся вручную. Пока ссылка не вписана, сайт показывает
   баннер с сообщением об этом вместо мероприятий.
2. **Автопоказ текущего месяца** — реализовано: при заходе на сайт
   открывается лист, соответствующий текущему календарному месяцу. Если
   для него нет данных (см. п.3), просто показывается пустой календарь
   с сообщением — а не редирект на другой месяц.
3. **Лист ещё не создан / конец списка месяцев** — показывается пустая
   сетка без подсветки + баннер «Лист «‹месяц›» ещё не заполнен».
   Стрелки навигации свободно листают все 12 месяцев учебного года по
   кругу (сентябрь → …→ август → сентябрь), независимо от того, созданы
   ли уже соответствующие листы — так следующие месяцы, добавляемые в
   таблицу по мере необходимости, подхватятся без правок кода.
4. **Совмещение двух цветовых сигналов на ячейке** — реализовано так:
   *«Вид мероприятия»* — пастельная заливка фона всей ячейки цветом
   категории (плюс те же цветные точки в углу — для точной идентификации
   и та же легенда под календарём); если за день несколько разных
   категорий — фон делится на равные диагональные полосы. *«Участие»*
   (`Да`/`Нет`) — компактные зелёная/красная точки внизу слева ячейки,
   отдельно от заливки, чтобы не спорить с ней за фон.
5. **Цвета категорий «Вид мероприятия»** — точный список категорий в ТЗ не
   был зафиксирован изначально, поэтому в `js/app.js` задан пример списка с
   закреплёнными цветами (`CATEGORY_COLOR_MAP`): Собрание/Экскурсия/
   Праздник/Кружок/Другое — тот же список используется в
   `apps-script/Code.gs` для выпадающего списка в таблице. Категория, не
   входящая в этот список (вписанная мимо выпадающего списка), всё равно
   получит цвет автоматически — из резервной палитры `FALLBACK_PALETTE`, по
   порядку первого появления. При изменении реальных категорий класса
   обновите оба списка (в `Code.gs` и в `js/app.js`), чтобы они совпадали.
6. **Значение «нет» в столбце «Время»** — трактуется как «время не указано»,
   а не как признак отсутствия мероприятия: наличие/отсутствие мероприятия
   в дне определяется исключительно непустым полем «Мероприятие» (как и
   зафиксировано в п.2 ТЗ). Значение столбца «Время» просто отображается
   в карточке дня как есть.

## Проверка

Открыть `index.html` через локальный веб-сервер (например
`python3 -m http.server`, т.к. `fetch` с `file://` может блокироваться
браузером) — после того как в `js/config.js` указана рабочая ссылка
`webAppUrl`.
