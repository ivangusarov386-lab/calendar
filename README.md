# Сайт-календарь на Google Таблице

Статический сайт (HTML/CSS/JS, без сборщиков), читающий данные напрямую из
Google Таблицы через Google Sheets API v4 при каждой загрузке страницы и
смене месяца — без собственного кэша.

## Структура

- `index.html` — разметка страницы
- `css/style.css` — стили (светлая тема, адаптивная сетка)
- `js/config.js` — **spreadsheetId** и **apiKey** (ключ нужно вписать самостоятельно, см. ниже)
- `js/app.js` — вся логика: загрузка данных, рендер сетки, модалка мероприятия

## Настройка API-ключа

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект.
2. В разделе **APIs & Services → Library** включите **Google Sheets API**.
3. В разделе **APIs & Services → Credentials** создайте **API key**.
4. Ограничьте ключ: **Application restrictions → Websites**, укажите домен сайта
   (например `your-domain.ru/*`); **API restrictions** — только Google Sheets API.
5. В самой таблице: **Настройки доступа → Все, у кого есть ссылка → Читатель**
   (без этого публичный ключ не сможет её прочитать).
6. Вставьте полученный ключ в `js/config.js`, поле `apiKey`.

Ключ read-only и виден в коде фронтенда — это ожидаемо для публичного ключа,
ограниченного по домену; запись через него в таблицу невозможна.

## Хостинг

Обычный статический сайт — выложить рядом с остальными проектами на VPS
(достаточно раздать `index.html`, `css/`, `js/` через любой веб-сервер:
nginx, Apache и т.п.). Сборка не требуется.

## Решения по открытым вопросам ТЗ (раздел 7)

Часть пунктов требовала доступа к Google Cloud Console пользователя или
данным, которых ещё нет в таблице — по ним приняты решения по умолчанию,
их при необходимости легко поменять в `js/app.js`:

1. **API-ключ** — не создавался (нет доступа к Google-аккаунту пользователя).
   `js/config.js` содержит плейсхолдер `apiKey`, который нужно заполнить
   вручную по инструкции выше. Пока ключ не заполнен, сайт показывает
   баннер с сообщением об этом вместо мероприятий.
2. **Автопоказ текущего месяца** — реализовано: при заходе на сайт
   открывается лист, соответствующий текущему календарному месяцу. Если
   для него нет данных (см. п.3), просто показывается пустой календарь
   с сообщением — а не редирект на другой месяц.
3. **Лист ещё не создан / конец списка месяцев** — показывается пустая
   сетка без подсветки + баннер «Лист «‹месяц›» ещё не заполнен».
   Стрелки навигации свободно листают все 12 месяцев учебного года по
   кругу (сентябрь → …→ август → сентябрь), независимо от того, созданы
   ли уже соответствующие листы — так следующие месяцы, добавляемые в
   таблицу по мере необходимости, подхватятся без правок кода.
4. **Совмещение двух цветовых сигналов на ячейке** — реализовано так:
   *«Вид мероприятия»* — цветные точки (маркеры) в правом верхнем углу
   ячейки, свой цвет на категорию (и та же цветовая легенда под
   календарём). *«Участие»* — светло-зелёный/светло-красный фон всей
   ячейки (`Да`/`Нет`); если в один день есть события с обоими значениями —
   фон делится по диагонали зелёный/красный.
5. **Цвета категорий «Вид мероприятия»** — точный список категорий в ТЗ
   не зафиксирован, поэтому цвет назначается автоматически из фиксированной
   палитры (`PALETTE` в `js/app.js`) по мере первого появления категории в
   данных и остаётся закреплённым за ней до перезагрузки страницы. Если
   нужен конкретный список категорий с закреплёнными цветами — его легко
   зашить явной картой `{ 'собрание': '#...', 'экскурсия': '#...' }` вместо
   автоназначения.
6. **Значение «нет» в столбце «Время»** — трактуется как «время не указано»,
   а не как признак отсутствия мероприятия: наличие/отсутствие мероприятия
   в дне определяется исключительно непустым полем «Мероприятие» (как и
   зафиксировано в п.2 ТЗ). Значение столбца «Время» просто отображается
   в карточке дня как есть.

## Проверка

Открыть `index.html` через локальный веб-сервер (например
`python3 -m http.server`, т.к. `fetch` с `file://` может блокироваться
браузером) — после того как в `js/config.js` указан рабочий API-ключ.
